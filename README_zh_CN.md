[English](README.md)

适用于 Minecraft Forge 1.20.1 的在线视频同步播放模组。服务端维护权威播放会话和时钟，
客户端使用 FFmpeg 在本地解码音视频，并将画面显示在连续的多方块屏幕上。本模组的目标
是在降低服务端开销的同时，为所有玩家提供流畅、稳定且同步的播放体验。

## 功能

- 服务端统一控制点播媒体的暂停、恢复、跳转、重连和中途加入同步；直播流由各客户端在
  当前直播边缘独立播放，并在本地验证完成后立即开始，不等待其他客户端。
- 支持墙面、地面与天花板屏幕，最大尺寸为 1024 x 1024 方块。
- 不同屏幕可通过各自的视频管理器同时运行独立播放会话。
- 可选择 FFmpeg CLI 或 VLCJ/LibVLC 客户端解码后端播放 HTTP(S) MP4、HLS 和 DASH 音视频分流。
- 屏幕音频可选择位置衰减、在可配置的 1-1024 格范围内保持恒定音量，或全服满音量广播。
- 同时提供 `/video` 命令和游戏内视频管理器 GUI。
- 仅开发版支持：游戏中按 F8 可预览当前 OpenGL 视频纹理和解码状态。
- 屏幕面板、视频管理器和可重复使用的屏幕选区工具均可合成，支持不会凭空生成屏幕方块的
  正常生存玩法。
- 屏幕所有者可在视频管理器中授予播放或修改权限，并可从按距离排序的列表中选择已加载且
  有修改权限的屏幕。
- 每位玩家必须先同意屏幕播放，服务端才会向该客户端发送媒体会话及请求凭据。
- 视频管理器支持批量输入 HTTP 请求头和 Cookie。
- 支持硬件解码回退和高分辨率视频自动缩放。

## 环境要求

- Minecraft Forge 1.20.1
- Java 17
- 使用 `no-ffmpeg` 版本时，需要在 `PATH` 中提供 FFmpeg 和 ffprobe
- 选择 VLCJ 后端的客户端还需要安装兼容的 VLC/LibVLC。Windows 客户端会自动搜索标准的
  VideoLAN 安装目录；如果安装在其他位置，请使用 `-Dvideo_synchronizer.vlcPath=<VLC 目录>`
  启动 Java，并确保目录中存在 `libvlc.dll`、`libvlccore.dll` 和 `plugins`。VLC 与 Java
  必须使用相同的体系结构。

请根据客户端系统选择 Linux 或 Windows 的 AMD64、ARM64 版本，这些版本已内嵌 FFmpeg。
平台无关的 `no-ffmpeg` 版本使用 `PATH` 中已有的 FFmpeg。Modrinth 将五种选择发布为
独立版本，请根据版本号中的平台后缀下载。

## 快速开始

先合成生存玩法所需物品：

- 6 个屏幕面板：玻璃板、黑色混凝土和红石。
- 视频管理器：屏幕面板、比较器、铁锭和红石。
- 屏幕选区工具：木棍、铁锭和红石火把。

以相同朝向放置一块矩形屏幕面板区域。用屏幕选区工具点击两个角，再输入屏幕 ID。工具只
组合已经放置的面板，不会生成方块；潜行使用可清除未完成的选区。创建者会成为所有者。
放置视频管理器，从按距离排序的列表中选择有修改权限且已加载的屏幕，保存 HTTP(S) 媒体
直链并开始播放。

管理器的授权界面可向其他玩家授予“播放”或“修改”权限。播放权限可控制已保存媒体，
修改权限还可更改链接和设置。访问模式包括：私有（仅所有者）、授权玩家（所有者和已授权
玩家）、公开控制（所有人可控制）和公开查看（所有人可查看状态，但未经授权不能控制）。
新屏幕默认为私有。OP 可管理所有屏幕。每个逻辑屏幕只保存一份所有者和权限记录，各面板
只引用该逻辑屏幕。

右键屏幕或其视频管理器可允许当前客户端播放。在玩家同意前，服务端不会向该玩家发送
屏幕媒体会话，也不会将其计入预载和时钟共识。潜行右键任一方块可重新查看或撤销同意。
屏幕所有者在创建屏幕时会自动同意；播放控制权限不能代替其他玩家作出观看同意。授权界面
会显示屏幕所有者，以及当前播放请求的发起玩家。

```text
/video start <屏幕ID> <HTTP或HTTPS地址>
/video pause <屏幕ID>
/video resume <屏幕ID>
/video seek <屏幕ID> <毫秒>
/video stop <屏幕ID>
/video trust <屏幕ID> <玩家> editor|controller
/video untrust <屏幕ID> <玩家>
/video access <屏幕ID> private|trusted|public_control|public_view
/video transfer <屏幕ID> <玩家>
/video info <屏幕ID>
/video sync
/video status
/video status bossbar
```

`transfer`、全局 `/video stop`、玩家权重、全局绑定以及不带屏幕 ID 的命令仍只允许管理员
执行。`/video create <屏幕ID> <宽度> <高度>` 是管理员建造命令；普通生存创建必须消耗已经
放置的面板。

服务端可通过 Forge 权限节点覆盖默认玩家权限：`video_synchronizer.create`、
`video_synchronizer.bind`、`video_synchronizer.edit_source`、
`video_synchronizer.control`、`video_synchronizer.remove` 和
`video_synchronizer.admin`。

## 使用须知

- 新的点播会话和跳转会等待大多数在线客户端准备完成；直播会话在第一个客户端本地验证
  完成后开始，其他客户端从各自的直播边缘加入；重连和中途加入的玩家会自动同步。
- 直播保留直播边缘输入时序和小画面的自动管线路径；设置的管线数量和长时间播放时按视频
  时钟重对齐音频仅用于点播媒体。
- 执行 `/video sync` 或重新进入屏幕音频范围后，会在解码器启动前写入服务端权威进度；
  真正启动 FFmpeg 前，播放中的会话会把媒体探测期间经过的时间计入该进度，暂停和预载
  阶段则保持服务端给出的精确位置。
- 非零位置首次同步时，FFmpeg 最多从目标前 4 秒打开，再快速丢弃这段预滚音视频且不
  显示，为远程媒体提供更可靠的较早关键帧；首个可见帧仍对应当前服务端时间。
- 客户端启动时会校验所选解码后端：FFmpeg 后端同时校验 `ffmpeg` 和 `ffprobe`，VLCJ
  后端校验 LibVLC；校验失败的客户端无法播放视频，也不会计入预载门槛和时钟共识。
- 客户端会先使用受限的媒体信息探测，避免长视频在启动时过度缓冲；快速结果不完整时会
  自动改用完整探测。
- 同一 URL 且视频仅使用单输出通道时，客户端使用一个 FFmpeg 进程解码音视频。原始视频
  使用多通道输出时，音频会从同一同步位置启动独立解码器，避免音频反压同时阻塞所有视频
  通道；配置独立音视频 URL 时也使用独立进程。
- 首个视频帧建立播放时钟前，共享音轨会按实际读到的部分字节持续排空并丢弃，避免任意
  同步起点先产生音频时，共享音频套接字反压 FFmpeg 并阻塞视频首帧。
- 音频或视频卡住时，两路会一起恢复。点播媒体从同步位置重新开始，直播媒体则重新连接
  当前直播边缘。
- 同步校正期间当前音视频会继续正常播放，替换解码器在后台准备首帧和首段音频，并丢弃
  落后于预计切换时间的帧，全部就绪后再在目标位置一起切换。
- 不超过 30 秒的向前校正会保留当前 FFmpeg 进程并快速丢弃旧视频帧和音频采样；追赶
  目标固定为收到的服务端时间稍后位置，避免较慢客户端因目标持续前移而永远无法追上。
  追上后本地时钟按实际追赶耗时对齐，而不会把预解码余量计入上报进度；更大跨度或向后
  校正仍使用 FFmpeg 跳转，小于一秒的校正只调整本地时钟。
- 单纯落后于播放时钟不会重启 FFmpeg。有界帧队列会保留最新的可用视频帧，只有确认输出
  卡住或解码失败时才重启解码器。
- 直播解码器使用独立的首个关键帧启动窗口；开始输出后，所有视频管线共用字节进度监控，
  仅在达到直播卡顿间隔且没有任何输出进展时重启解码器。
- 常规漂移校正会等待完整的 5 秒采样窗口，仅在平均偏差持续达到 750 毫秒时跳转，避免
  刚开始播放或突发延迟尖峰触发跳转。
- FFmpeg 收到 HTTP 403 时，会使用会话最初的 URL 重试至多 5 次，之后才上报 HTTP 错误。
- `/video sync` 是客户端命令，会先停止本地视频和音频，再请求服务器权威进度并从该进度
  重新播放；对于直播媒体，它会改为重新连接当前直播边缘。
- 音频定位在屏幕中心。每个视频管理器单独保存最远范围，默认值为 48 格，也可切换为
  范围内恒定音量。全服广播会在所有维度以完整音量播放，并且只有 OP 可以配置或启动。
- 在位置衰减模式下，范围外客户端不会启动 FFmpeg，并会释放已有的解码器、音频、帧和
  纹理资源；重新进入范围后会从服务端当前权威进度加载。
- `/video status` 只列出玩家有权查看的会话，并将范围外的位置会话标为已卸载；其 Boss
  Bar 只跟踪该玩家应加载的会话。
- 链接必须提供 FFmpeg 可直接读取的媒体流。视频链接没有视频流，或配置的独立音频链接
  没有音频流时，播放会停止，并在物品栏上方显示红色加粗提示。
- 普通玩家的控制命令必须带 `screen_id`；不带 ID 的暂停、继续、跳转和停止仅用于管理员
  及命令启动的会话。
- 已知媒体时长播放完毕后会自动停止；直播流不参与播放时间共识或漂移跳转，会禁用跳转
  控件，并需要手动停止。
- 媒体地址、请求头和 Cookie 会发送到客户端用于本地解码，请勿使用不应向在线玩家公开
  的凭据。
- 默认拒绝内网、回环、链路本地和本地域名媒体地址，并且不会向非管理员发送或允许其修改
  已保存的自定义请求头和 Cookie。服务端配置可设置域名白名单、每位玩家的屏幕/面板/
  活动会话上限，以及创建和播放冷却时间。
